# 童趣成长乐园生产发布指引

## 1. 文档用途

本文用于把当前 `main` 分支发布到 `https://playmori.online`，覆盖首次服务器准备、日常版本发布、数据库迁移、手机号登录验收和回滚。逐项验收标准另见 [`生产发布清单.md`](生产发布清单.md)。

当前生产结构：

```text
浏览器 → HTTPS / Nginx → 127.0.0.1:4173 / Node.js
                                  ├── 阿里云 RDS MySQL
                                  ├── 阿里云号码认证服务
                                  └── DeepSeek API
```

发布原则：先备份、再迁移、再重启；任何一步失败都停止后续操作。真实密钥只保存在服务器，不写入 Git、聊天记录或前端代码。

## 2. 发布前必须具备

- 域名和 HTTPS 证书有效。
- 服务器安装 Node.js 20 或更高版本、npm、Git、Nginx、`mysqldump` 和 `curl`。
- 阿里云 RDS MySQL 8.0 可从 ECS 内网访问，应用账号拥有当前迁移所需权限。
- DeepSeek API Key 可用。
- 阿里云号码认证服务已开通“短信认证”，已取得当前可用的赠送签名和登录/注册模板。
- 已创建独立 RAM 用户及 AccessKey，只绑定以下权限：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dypns:SendSmsVerifyCode",
        "dypns:CheckSmsVerifyCode"
      ],
      "Resource": "*"
    }
  ]
}
```

- 个体工商户正式名称、公开联系渠道和隐私邮箱已经确定。
- 本次发布代码已经提交，并完成 `npm test`。

## 3. 服务器目录和权限（首次配置）

运维示例默认使用以下路径：

```text
代码目录：/var/www/kids-learning-games
环境文件：/etc/playmori/playmori.env
统计目录：/var/lib/playmori/analytics
备份目录：/var/backups/playmori
服务用户：playmori
```

首次配置时创建服务用户和受限目录。若用户已经存在，不要重复执行 `useradd`：

```bash
id playmori
sudo useradd --system --home /var/lib/playmori --shell /usr/sbin/nologin playmori
sudo install -d -o playmori -g playmori -m 700 /var/lib/playmori/analytics
sudo install -d -o playmori -g playmori -m 700 /var/backups/playmori
sudo install -d -o root -g playmori -m 750 /etc/playmori
sudo touch /etc/playmori/playmori.env
sudo chown root:playmori /etc/playmori/playmori.env
sudo chmod 640 /etc/playmori/playmori.env
```

环境文件使用 `root:playmori 640`：管理员可以修改，服务用户只能读取，其他用户无权访问。

## 4. 生产环境变量

编辑 `/etc/playmori/playmori.env`，替换所有尖括号占位值。包含空格或中文的值使用双引号：

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=4173

DEEPSEEK_API_KEY=<真实密钥>
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com

DB_ENABLED=true
DB_HOST=<RDS内网地址>
DB_PORT=3306
DB_NAME=playmori
DB_USER=<应用账号>
DB_PASSWORD=<数据库密码>
DB_CONNECTION_LIMIT=5
DB_CONNECT_TIMEOUT=10000
DB_SSL=false
DB_SSL_REJECT_UNAUTHORIZED=true
DB_SSL_CA_PATH=

ANALYTICS_ENABLED=true
ANALYTICS_SALT=<独立随机密钥>
ANALYTICS_DIR=/var/lib/playmori/analytics
ANALYTICS_RETENTION_DAYS=30

SESSION_COOKIE_NAME=playmori_session
SESSION_COOKIE_SECURE=true
SESSION_TTL_DAYS=30
ACCOUNT_IDENTITY_HASH_SECRET=<独立随机密钥>
ACCOUNT_IDENTITY_ENCRYPTION_KEY=<独立随机密钥>
PHONE_OTP_SECRET=<独立随机密钥>
PHONE_OTP_TTL_MINUTES=5
PHONE_CHALLENGE_RETENTION_DAYS=30

SMS_PROVIDER=aliyun-auth
ALIBABA_CLOUD_ACCESS_KEY_ID=<RAM用户AccessKey ID>
ALIBABA_CLOUD_ACCESS_KEY_SECRET=<RAM用户AccessKey Secret>
ALIYUN_SMS_AUTH_SIGN_NAME="<控制台当前可用的赠送签名>"
ALIYUN_SMS_AUTH_TEMPLATE_CODE=<登录注册模板编号>
ALIYUN_SMS_AUTH_SCHEME_NAME=

PUBLIC_OPERATOR_NAME="<个体工商户完整名称>"
PUBLIC_CONTACT_CHANNEL="<公众号、电话或其他联系渠道>"
PUBLIC_PRIVACY_EMAIL=<隐私邮箱>

BACKUP_DIR=/var/backups/playmori
BACKUP_RETENTION_DAYS=30
```

使用以下命令分别生成四组密钥，不能复用：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

依次用于 `ANALYTICS_SALT`、`ACCOUNT_IDENTITY_HASH_SECRET`、`ACCOUNT_IDENTITY_ENCRYPTION_KEY` 和 `PHONE_OTP_SECRET`。身份加密密钥投入使用后不能直接更换。

项目命令行工具支持通过 `PLAYMORI_ENV_FILE` 读取服务器环境文件。不要把生产环境文件复制到代码目录：

```bash
sudo -u playmori env PLAYMORI_ENV_FILE=/etc/playmori/playmori.env npm run check:production
```

## 5. 首次安装 systemd、备份定时器和 Nginx

先检查 `ops/` 中的工作目录、Node 路径和域名是否与服务器一致，再安装：

```bash
sudo cp ops/playmori.service.example /etc/systemd/system/playmori.service
sudo cp ops/playmori-backup.service.example /etc/systemd/system/playmori-backup.service
sudo cp ops/playmori-backup.timer.example /etc/systemd/system/playmori-backup.timer
sudo systemctl daemon-reload
sudo systemctl enable playmori.service
sudo systemctl enable --now playmori-backup.timer
```

安装 Nginx 配置：

```bash
sudo cp ops/nginx-playmori.conf.example /etc/nginx/sites-available/playmori
sudo ln -s /etc/nginx/sites-available/playmori /etc/nginx/sites-enabled/playmori
sudo nginx -t
sudo systemctl reload nginx
```

若服务器不是 Debian/Ubuntu，请使用当前系统对应的 Nginx 配置目录。证书文件不存在时，先申请或续期 Let's Encrypt 证书，再启用 HTTPS 配置。

## 6. 日常发布步骤

### 6.1 发布前记录版本

```bash
cd /var/www/kids-learning-games
git status --short
git rev-parse HEAD
```

工作区必须为空。记录旧提交编号，供回滚使用。服务器上不得直接修改业务代码。

### 6.2 拉取代码和安装依赖

```bash
git fetch origin
git checkout main
git pull --ff-only origin main
npm ci
npm audit --omit=dev
npm test
```

任何命令失败都停止发布，不执行数据库迁移和服务重启。

### 6.3 备份数据库

```bash
sudo -u playmori env PLAYMORI_ENV_FILE=/etc/playmori/playmori.env npm run db:backup
sudo ls -lh /var/backups/playmori
```

确认生成新的 `.sql.gz` 文件且大小不是 0。首次启用账号体系时，必须保留发布前备份。

### 6.4 执行迁移和生产检查

```bash
sudo -u playmori env PLAYMORI_ENV_FILE=/etc/playmori/playmori.env npm run db:migrate
sudo -u playmori env PLAYMORI_ENV_FILE=/etc/playmori/playmori.env npm run db:check
sudo -u playmori env PLAYMORI_ENV_FILE=/etc/playmori/playmori.env npm run check:production
```

账号体系首次发布会依次应用 `004`～`008` 迁移。迁移脚本是追加式的；已经写入 `schema_migrations` 的文件不会重复执行。

### 6.5 检查并重启服务

```bash
sudo nginx -t
sudo systemctl restart playmori
sudo systemctl status playmori --no-pager
sudo journalctl -u playmori -n 100 --no-pager
```

日志中不得出现 AccessKey、数据库密码、完整手机号或验证码。

## 7. 发布后自动检查

```bash
curl -fsS https://playmori.online/api/health
curl -I https://playmori.online/
curl -I https://playmori.online/account.html
curl -I https://playmori.online/.env
curl -I https://playmori.online/.git/config
curl -I https://playmori.online/server/config.mjs
```

预期结果：

- `/api/health` 返回 `ok: true`、数据库连接正常、短信 `provider` 和 `verificationMode` 均为 `aliyun-auth`。
- 首页和家庭空间返回 `200`。
- `.env`、`.git/config`、服务端源码均返回 `404`。
- 响应包含 HSTS、CSP、`X-Frame-Options: DENY` 和 `X-Content-Type-Options: nosniff`。

## 8. 账号和短信人工验收

使用专门测试手机号完成以下流程：

1. 未勾选协议时不能发送验证码。
2. 正确发送六位验证码，页面只显示脱敏手机号。
3. 错误验证码提示失败，五次错误后挑战锁定。
4. 验证码过期、重复使用和旧验证码均不能登录。
5. 首次正确登录创建成人账号、家庭和空白默认儿童使用位。
6. 未同意儿童规则时不能同步；同意后可以同步故事、收藏和识字记录。
7. 第二台设备登录后可以找回家庭数据。
8. “退出当前设备”和“退出全部设备”均有效。
9. “清空成长数据”删除家庭故事、收藏、识字进度和设备认领，但保留成人账号。
10. 刚完成登录 15 分钟内可以注销单成员家庭账号；注销后原会话失效。

确认 Nginx 和应用日志只出现脱敏信息。验收完成后删除测试产生的数据或注销测试账号。

## 9. 备份定时器检查

```bash
sudo systemctl status playmori-backup.timer --no-pager
sudo systemctl list-timers playmori-backup.timer --all
sudo systemctl start playmori-backup.service
sudo journalctl -u playmori-backup.service -n 50 --no-pager
```

每日备份默认在 03:20 后随机延迟不超过 20 分钟执行，备份文件默认保留 30 天。上线前至少完成一次恢复到空测试库的演练。

## 10. 回滚

应用异常但数据库迁移成功时，保留追加式迁移，只回滚代码：

```bash
cd /var/www/kids-learning-games
git checkout <发布前提交编号>
npm ci
sudo nginx -t
sudo systemctl restart playmori
sudo systemctl status playmori --no-pager
```

确认旧版本稳定后，再决定是否恢复 `main`。不要执行 `git reset --hard`，也不要手工删除迁移记录。

只有数据库数据损坏或迁移中断时才恢复备份，并优先恢复到一套新数据库进行核验：

```bash
gzip -dc /var/backups/playmori/<备份文件>.sql.gz | mysql -h <测试库地址> -u <恢复账号> -p <测试库名>
```

恢复后执行 `npm run db:check`，确认表结构和数据正常，再切换应用连接。生产事故应记录时间、版本、影响、处置过程和后续改进。

## 11. 常见问题

### 生产检查提示短信未配置

确认 `SMS_PROVIDER=aliyun-auth`，AccessKey、赠送签名和模板编号均已填写，并且 RAM 用户只绑定了发送与核验权限。赠送签名可能因阿里云调整而变化，应以号码认证控制台当前值为准。

### 命令行读取不到生产配置

确认命令包含：

```text
PLAYMORI_ENV_FILE=/etc/playmori/playmori.env
```

并确认文件权限为 `root:playmori 640`，服务用户具有读取权限。

### 服务启动但 Nginx 返回 502

检查：

```bash
sudo systemctl status playmori --no-pager
sudo journalctl -u playmori -n 100 --no-pager
ss -lntp | grep 4173
```

Node 服务必须只监听 `127.0.0.1:4173`，不能向公网开放该端口。

### 短信发送成功但验证码无法核验

确认发送和核验使用相同的 `ALIYUN_SMS_AUTH_SCHEME_NAME`；留空时两边都使用默认方案。不要在发送后修改方案名、签名或模板再继续验证旧验证码。
